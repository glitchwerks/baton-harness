# CodeReeve 0.2.0 release notes

> **UNRELEASED:** These notes describe the planned 0.2.0 release. The release,
> live-systemd acceptance, primary merge, artifact publication, and repository
> rename have not occurred. Issue #396 remains the release gate.

CodeReeve 0.2.0 establishes the `codereeve` package and command tree, the
`CODEREEVE_*` configuration namespace, `.codereeve` managed state, and
`codereeve.service` as the canonical identities. The predecessor names remain
temporary compatibility inputs through the 0.3.x line and are scheduled for
removal in 0.4.0 (#390; #396).

## Install and verify

Build and verify artifacts from one exact clean source revision, then install
the wheel into a new environment. The old and candidate distributions must not
share an environment (`docs/codereeve-release-gate.md#installed-release-proof`;
`src/codereeve/verify_foundation.py:L530-L649`; #396).

```bash
uv venv /opt/codereeve --python 3.13
uv pip install --python /opt/codereeve/bin/python ./codereeve-0.2.0-py3-none-any.whl
/opt/codereeve/bin/codereeve verify --installed
/opt/codereeve/bin/codereeve provenance
/opt/codereeve/bin/codereeve doctor --phase installation --strict
/opt/codereeve/bin/codereeve doctor --phase configuration --strict
```

New automation should invoke `codereeve daemon`, `codereeve hook after-create`,
`codereeve hook before-run`, and `codereeve doctor`. The complete command and
configuration mapping is maintained in the README migration tables
(`README.md:L286-L396`; #396).

## Migrate and cut over the service

The migration inventory and apply commands are `codereeve migrate --check` and
`codereeve migrate --apply`. Apply preserves original bytes and metadata in
private backups and emits a durable journal used for restoration
(`docs/codereeve-migration.md:L63-L118`; #396).

For a systemd deployment, install the candidate in its own environment and use
the private installer first with `--print-unit`, then `--no-start`, before the
full cutover. The coordinator accepts explicit `--harness-dir`, `--project-root`,
`--environment`, and `--user` selections. Recover an interrupted transaction
with `--recover JOURNAL` (`docs/codereeve-service-cutover.md:L19-L65`;
`src/codereeve/service_cutover/cli.py:L28-L41`; #396).

Rollback keeps the predecessor environment untouched and proves its executable,
configuration, files, activation state, and writer quiescence before allowing
old-service activation (#396;
`src/codereeve/service_cutover/recovery.py:L224-L365`). An interrupted write to
an original public file can require manual recovery: unknown, empty, or partial
public bytes are preserved, the verified private backup is retained, recovery
stays incomplete, and the old service remains stopped until an operator repairs
the public file from trusted evidence
(`src/codereeve/service_cutover/recovery.py:L134-L219`; #396).

## Compatibility and remaining release gates

The 0.2 and 0.3 release lines accept the documented predecessor command,
environment, path, and unit identities only as migration or compatibility
inputs. Their removal is reserved for 0.4.0. Third-party identifiers and the
vendored Symphony provenance remain unchanged (#390; #396).

The downstream work in #361, #378, #379, #380, #381, #382, #383, #243, and
#168 consumes the canonical command/package, environment, and state interfaces.
Those issues retain their own remaining scope and are not completed by this
release-note preparation. The 1.0 release remains blocked on #390 until the
0.3 compatibility cycle and 0.4 removal work are complete (#390; #396).

Repository links in these notes and the README still use the current repository
name. The repository rename is the last external cutover step after successful
canonical installation; redirects are not acceptance evidence (#396).
