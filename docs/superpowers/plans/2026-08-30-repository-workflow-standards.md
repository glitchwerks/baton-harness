# Repository Workflow Standards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add enforceable issue, branch, pull-request, validation, review, milestone, and label standards for repository work.

**Architecture:** Pure Python evaluates branch names, closing directives, and linked-issue milestones; a read-only GitHub Actions adapter supplies live issue metadata. Separate workflows keep branch feedback fast and reserve the existing full suite plus PR policy for pull requests to `main`. Repository templates, CodeRabbit configuration, human documentation, and equivalent agent instructions make the policy visible at every entry point.

**Tech Stack:** Python 3.10, pytest, PyYAML, GitHub Actions YAML, GitHub issue forms, Markdown, CodeRabbit YAML, GitHub REST/MCP.

**Spec:** `docs/superpowers/specs/2026-08-30-repository-workflow-standards-design.md`

## Global Constraints

- Branches must match `<type>/<issue-number>-<slug>` with type exactly `feature`, `bug`, `docs`, `chore`, or `refactor` (`docs/superpowers/specs/2026-08-30-repository-workflow-standards-design.md:L44-L55`).
- Fast validation runs Ruff lint/format, ShellCheck, and `pytest -m fast` on non-main work branches; full Ruff, ShellCheck, mypy, and pytest run on PRs to `main` (`docs/superpowers/specs/2026-08-30-repository-workflow-standards-design.md:L107-L131`).
- Preserve the full-suite check names `Lint (ruff)`, `Lint (shellcheck)`, `Type check (mypy)`, and `Test (pytest)` because code, CI, and the checked-in target ruleset are contractually synchronized (`tests/test_required_checks_match_ci_yml.py:L1-L12`, `tests/test_required_checks_match_ci_yml.py:L87-L112`).
- `PR policy` must reject invalid branch names, missing closing directives, branch/issue mismatch, and every closing issue without a milestone (`docs/superpowers/specs/2026-08-30-repository-workflow-standards-design.md:L133-L160`).
- Issue forms contain only pre-merge acceptance criteria; CI does not parse acceptance-criteria prose or checkbox state (`docs/superpowers/specs/2026-08-30-repository-workflow-standards-design.md:L67-L89`).
- `needs-review` is a PR-only, advisory CodeRabbit trigger: always for features, never for docs-only changes, and risk-evaluated for bugs, chores, and refactors (`docs/superpowers/specs/2026-08-30-repository-workflow-standards-design.md:L162-L181`).
- Do not change `config/ruleset.main.json`; it configures target-sandbox daemon checks, not this repository's governance (`docs/superpowers/specs/2026-08-30-repository-workflow-standards-design.md:L154-L160`).
- Do not change or remove daemon operational labels; their state invariant is implemented in `src/baton_harness/chain/labels.py:L20-L55`.
- Keep `AGENTS.md` and `CLAUDE.md` byte-identical after adding the repository workflow policy (`docs/superpowers/specs/2026-08-30-repository-workflow-standards-design.md:L198-L204`).
- Use the project interpreter `./.venv/Scripts/python.exe` for every local Python command; the project declares Python `>=3.10` and the development tools in `pyproject.toml:L1-L31`.
- Every new Python module, class, function, and test has complete type hints and a Google-style docstring; the repository enforces annotation and pydocstyle rules in `pyproject.toml:L51-L78`.
- Put GitHub token permissions on the job that needs them, and add concurrency cancellation to PR workflows; this follows the mandatory least-privilege and duplicate-run guidance in the `github-actions` skill applied to this plan.
- Every GitHub issue/PR body or comment written by an agent ends with `> 🤖 _Generated by Codex on behalf of @cbeaulieu-gt_` (repository `AGENTS.md` instructions supplied for this work).

```python
BRANCH_PATTERN = re.compile(
    r"^(?:feature|bug|docs|chore|refactor)/"
    r"(?P<issue>[1-9][0-9]*)-[a-z0-9]+(?:-[a-z0-9]+)*$"
)
CLOSING_PATTERN = re.compile(
    r"\b(?:closes|fixes|resolves)\s+"
    r"(?:(?P<repository>[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+))?"
    r"#(?P<issue>[1-9][0-9]*)\b",
    re.IGNORECASE,
)


def parse_branch_issue(head_ref: str) -> int | None:
    match = BRANCH_PATTERN.fullmatch(head_ref)
    return int(match.group("issue")) if match else None


def parse_closing_issues(body: str, repository: str) -> tuple[int, ...]:
    numbers: list[int] = []
    for match in CLOSING_PATTERN.finditer(body):
        qualified_repo = match.group("repository")
        if qualified_repo and qualified_repo.casefold() != repository.casefold():
            continue
        number = int(match.group("issue"))
        if number not in numbers:
            numbers.append(number)
    return tuple(numbers)


def evaluate_pr_policy(
    head_ref: str,
    body: str,
    repository: str,
    issue_has_milestone: Mapping[int, bool],
) -> list[str]:
    errors: list[str] = []
    branch_issue = parse_branch_issue(head_ref)
    closing_issues = parse_closing_issues(body, repository)
    if branch_issue is None:
        errors.append(f"invalid source branch: {head_ref}")
    if not closing_issues:
        errors.append("PR body has no closing directive for this repository")
    elif branch_issue is not None and branch_issue not in closing_issues:
        errors.append(
            f"branch issue #{branch_issue} is not closed by the PR body"
        )
    for issue_number in closing_issues:
        if issue_number not in issue_has_milestone:
            errors.append(
                f"unable to verify milestone for closing issue #{issue_number}"
            )
        elif not issue_has_milestone[issue_number]:
            errors.append(f"closing issue #{issue_number} has no milestone")
    return errors
```

Start the module with `"""Enforce repository pull-request metadata policy."""`, add `from __future__ import annotations`, order standard-library imports, and give every public/private function a complete Google-style docstring with `Args`, `Returns`, and `Raises` where applicable.

Implement `evaluate_pr_policy` so it accumulates errors in this order: invalid branch, missing closing directive, branch/issue mismatch, then one missing-milestone error per closing issue. Never index `issue_has_milestone` before checking the closing issue exists in the mapping; absence is a runtime-data error that Task 2 prevents, not evidence of a missing milestone.

```python
@dataclass(frozen=True)
class PullRequestEvent:
    head_ref: str
    body: str
    repository: str


class PolicyRuntimeError(RuntimeError):
    """Raised when live PR policy input cannot be read safely."""


def _request_json(request: urllib.request.Request) -> dict[str, object]:
    try:
        with urllib.request.urlopen(request, timeout=15) as response:
            payload = json.load(response)
    except (OSError, json.JSONDecodeError) as exc:
        raise PolicyRuntimeError("GitHub issue metadata request failed") from exc
    if not isinstance(payload, dict):
        raise PolicyRuntimeError("GitHub issue metadata was not a JSON object")
    return {str(key): value for key, value in payload.items()}


def fetch_issue_has_milestone(
    repository: str, issue_number: int, token: str
) -> bool:
    request = urllib.request.Request(
        f"https://api.github.com/repos/{repository}/issues/{issue_number}",
        headers={
            "Accept": "application/vnd.github+json",
            "Authorization": f"Bearer {token}",
            "X-GitHub-Api-Version": "2022-11-28",
        },
    )
    return _request_json(request).get("milestone") is not None


def load_pull_request_event(path: Path) -> PullRequestEvent:
    payload: object = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(payload, dict):
        raise PolicyRuntimeError("GitHub event was not a JSON object")
    repository_payload = payload.get("repository")
    pull_request_payload = payload.get("pull_request")
    if not isinstance(repository_payload, dict) or not isinstance(
        pull_request_payload, dict
    ):
        raise PolicyRuntimeError("GitHub event is missing PR metadata")
    head_payload = pull_request_payload.get("head")
    repository = repository_payload.get("full_name")
    body = pull_request_payload.get("body")
    if not isinstance(head_payload, dict) or not isinstance(repository, str):
        raise PolicyRuntimeError("GitHub event has invalid PR metadata")
    head_ref = head_payload.get("ref")
    if not isinstance(head_ref, str) or not (
        body is None or isinstance(body, str)
    ):
        raise PolicyRuntimeError("GitHub event has invalid PR fields")
    return PullRequestEvent(head_ref, body or "", repository)


def main(argv: Sequence[str] | None = None) -> int:
    del argv
    event_path = os.environ.get("GITHUB_EVENT_PATH")
    token = os.environ.get("GITHUB_TOKEN")
    if not event_path or not token:
        print("PR policy: required GitHub environment is missing", file=sys.stderr)
        return 1
    try:
        event = load_pull_request_event(Path(event_path))
        closing_issues = parse_closing_issues(event.body, event.repository)
        milestones = {
            number: fetch_issue_has_milestone(event.repository, number, token)
            for number in closing_issues
        }
        errors = evaluate_pr_policy(
            event.head_ref,
            event.body,
            event.repository,
            milestones,
        )
    except (OSError, json.JSONDecodeError, PolicyRuntimeError) as exc:
        print(f"PR policy: {exc}", file=sys.stderr)
        return 1
    for error in errors:
        print(f"PR policy: {error}", file=sys.stderr)
    return int(bool(errors))


if __name__ == "__main__":
    raise SystemExit(main())
```

`load_pull_request_event` must validate each nested object/string instead of relying on unchecked casts; a JSON `null` PR body becomes `""` so the normal missing-directive error is reported. `main` loads the event, parses closing issues, fetches milestone state for each closing issue, evaluates policy, prints each error as `f"PR policy: {error}"` to stderr, and returns `1` on policy/runtime errors or `0` on success. It must never print `GITHUB_TOKEN` or raw authorization headers.
